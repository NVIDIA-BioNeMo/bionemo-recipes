# Open upstream gaps

Open framework limitations affecting Stitch and its examples. Closed, merged,
adopted, withdrawn, and package-only items are removed. Merged fixes are omitted
even when the runtime pin has not adopted them; those remaining workarounds
keep their affected revision and deletion condition in code comments. Identifiers cited in workaround
comments stay stable and must not be reused. Stitch-owned open bugs and
capability gaps are tracked separately in [`bug-reports.md`](bug-reports.md).

These findings apply to the pinned example stack: NeMo RL `b03da0f4`,
AutoModel `1814c6c9`, PyTorch `2.11.0+cu130`, and vLLM `0.25.1`.
The snapshot is Stitch `c3f389af` (2026-10-02). Linked NeMo RL PRs below were
confirmed open on 2026-10-02. A fix must also reach the runtime pin before a
workaround can be deleted.

## Integration gaps

| ID               | Gap and current handling                                                                                                                                                      | Upstream change needed                                                                                                                                                                                                               |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| U-18             | **Generation-only HF overrides.** `nemo_rl/vllm_worker.py` translates the rollout architecture at engine construction.                                                        | Merge user generation overrides with policy overrides instead of replacing them in GRPO.                                                                                                                                             |
| U-26             | **Evaluation-only AutoModel recipes.** `ProjectorEvaluationRecipe` needs unused training setup and private validation lifecycle calls.                                        | Provide a public evaluation mode that restores state, runs validation loaders, reports metrics, and closes resources.                                                                                                                |
| U-29             | **Grouped-expert LoRA refit.** Routed-expert adapters cannot yet be used safely in GRPO; no local conversion shim.                                                            | Export every supported adapter into canonical base weights, or use an equivalent adapter-aware transfer. Candidates: [RL#3353](https://github.com/NVIDIA-NeMo/RL/pull/3353), [RL#3964](https://github.com/NVIDIA-NeMo/RL/pull/3964). |
| U-31             | **`logits_to_keep` detection.** `automodel/model.py` names the argument explicitly so fused loss remains enabled.                                                             | Recognize forwarded kwargs or a public loss-capability marker.                                                                                                                                                                       |
| U-34             | **Chat-boundary continuation encoding.** `FeatureCollator` preserves prompt tokens when Qwen chat rendering changes token boundaries.                                         | Provide prompt-preserving continuation encoding and masking that passes parity, EOS, and feature-index checks.                                                                                                                       |
| U-38             | **vLLM executor selection.** `_select_vllm_executor_backend` preserves the qualified multiprocessing executor.                                                                | Honor an explicit validated executor selection instead of overwriting it after `vllm_kwargs` composition.                                                                                                                            |
| U-41             | **Local-vocabulary logprob memory.** The pinned loss ignores training chunk size and setup forces FP32 FSDP outputs; `Dockerfile.candidates` supplies an optional PR overlay. | Adopt [RL#4114](https://github.com/NVIDIA-NeMo/RL/pull/4114) and [RL#4115](https://github.com/NVIDIA-NeMo/RL/pull/4115), then verify probabilities, gradients, and full-batch updates.                                               |
| U-45             | **Equal-pack loss normalization.** No Stitch training-loop workaround.                                                                                                        | Support per-pack means with correct accumulation and distributed scaling, verified on unequal-length packs.                                                                                                                          |
| U-47             | **Native checkpoints omit module-owned projector state.** GRPO publishes a portable projector artifact beside each checkpoint; AutoModel native SFT resume still needs a fix. | Save and restore matching projector and extra state atomically with native model and optimizer checkpoints.                                                                                                                          |
| U-52             | **Asynchronous checkpoint publication.** Failed saves can leave incomplete shards while reporting success; use public synchronous saves when needed.                          | Advance checkpoint status only after successful shard finalization and atomic publication; test background process-group failures.                                                                                                   |
| U-53             | **Mixed original dtypes in full-decoder FSDP2 training.** BF16 weights alongside intentional FP32 state fail uniform-dtype checks.                                            | Build uniform-dtype FSDP groups or expose a policy that preserves intentional FP32 parameters.                                                                                                                                       |
| U-54             | **DPO preference processor selection.** `nemo_rl/dpo.py` selects a processor through public `setup_preference_data` and uses the stock trainer.                               | Expose processor selection in the native DPO launcher/configuration so the package launcher can be deleted.                                                                                                                          |
| U-61             | **Refit exclusion for co-trained state.** The policy worker excludes projector weights from manifest, IPC, and NCCL refit; unsupported transports fail at admission.          | Provide one exclusion contract honored by every refit enumeration and transport.                                                                                                                                                     |
| U-63 (AutoModel) | **Out-of-tree multi-GPU recipe entrypoints.** Examples launch through `torchrun -m nemo_automodel.cli.app`.                                                                   | Resolve recipe modules from their import locations and reject non-runnable training scripts diagnostically.                                                                                                                          |
| U-63 (NeMo RL)   | **External-DP generation cluster size.** LLaVA config tests ensure the allocated cluster matches the EP/TP layout.                                                            | Validate generation world size against external DP before starting rendezvous.                                                                                                                                                       |
| U-64             | **Frozen-base evaluation initialization.** Native zero-update evaluation can leave the decoder trainable and fail the policy guard.                                           | Provide generation-only validation or a frozen-policy initialization mode.                                                                                                                                                           |
| U-65             | **Schedulers and late optimizer groups.** Joint projector GRPO admits only `ConstantLR(factor=1.0, total_iters=0)` and rejects unsafe schedules at construction.              | Let extensions contribute groups before scheduler construction, then verify milestone crossing and resume with those groups.                                                                                                         |
| U-66             | **Dense replication combined with expert parallelism.** Each mesh alone is admitted; the combination fails at construction.                                                   | Support dense replication within fused EP ranks, then qualify the projector on the combined mesh.                                                                                                                                    |
| U-68             | **Merged-PEFT export memory.** Layout conversion can exceed an 80 GiB GPU's memory; a host-conversion fix exists outside the pin.                                             | Move filtered state to host memory before conversion and verify the unmodified export CLI on the pinned stack.                                                                                                                       |
| U-70             | **Colocated external-DP vLLM scheduling.** The worker requires explicit `async_scheduling: false` for vLLM 0.25.1.                                                            | Support repeated generate/train/refit cycles with asynchronous scheduling, or enforce a validated upstream admission rule.                                                                                                           |

The upstream tracker assigned U-63 to two different framework issues. Both
labels are preserved with their framework names to avoid changing existing
references.

## Other open framework limitations

These are general framework issues rather than modality-integration requests.
They remain relevant to current code or configuration.

| ID   | Gap and current handling                                                                                                           | Upstream change needed                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| U-9  | **Colocated residency.** Policy and generation workers can retain weights on the GPU between phases.                               | Expose and qualify residency/offload configuration without application overrides.                                |
| U-15 | **Buffer placement.** Module-owned model buffers may miss framework device placement.                                              | Place persistent model buffers consistently with the owning module.                                              |
| U-16 | **Transformer Engine linear TP.** Custom linears are replaced with PyTorch linears retaining the same parameters.                  | Support the original linear types in AutoModel's TP plan.                                                        |
| U-17 | **TP×EP dispatch.** The integration applies the consumer TP plan before the generic EP path.                                       | Expose a supported composition hook for TP and EP strategies.                                                    |
| U-20 | **Validation sampling.** Examples need validation sampling that can differ from training rollouts.                                 | Expose separate validation sampling configuration.                                                               |
| U-21 | **Per-datum chat-template kwargs.** The dataset uses a tokenizer proxy to preserve row-specific rendering choices.                 | Transport template kwargs through the native data path.                                                          |
| U-30 | **Mamba `out_proj` LoRA.** Examples exclude the target because the fused branch reads its base weight directly.                    | Apply the adapter in the fused path, use a supported module path, or reject the target during PEFT construction. |
| U-32 | **Large Qwen synchronous generation batches.** Examples select the public Triton prefill backend.                                  | Make large submitted batches progress with bounded concurrency or fail diagnostically.                           |
| U-33 | **FP32 policy master weights.** Policy initialization can exceed single-GPU memory even with BF16 computation.                     | Expose a supported storage/precision policy with qualified numerical behavior.                                   |
| U-42 | **Positive-example NLL reward transport.** No local loss patch; enabling the objective without rewards can silently leave it zero. | Transport aligned rewards or a correctness mask to policy minibatches and reject unavailable enabled objectives. |
| U-44 | **Mamba2 batch-invariant evaluation.** vLLM 0.25.1 rejects batch-invariant mode for this backend.                                  | Support deterministic batch-invariant execution or expose the unsupported combination at admission.              |
| U-67 | **Asynchronous colocation and multi-loader admission.** No local runtime workaround.                                               | Qualify async colocation and balanced multi-loader admission through public NeMo RL configuration.               |
